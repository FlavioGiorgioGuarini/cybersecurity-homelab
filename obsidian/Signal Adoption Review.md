# Signal Adoption Review

Create a dated copy for a release or program application. Use the repository’s public records and cite each claim.

| Metric | Count or status | Window | Source link |
| --- | --- | --- | --- |
| Issues opened and closed | Unknown | Record separately | Public issue search |
| Pull requests merged | Unknown | Record threshold window | Public merged PR search |
| Unique external contributors with merged PRs | Unknown | Same window as PRs | Reviewed PR author list |
| Stars and forks | Unknown | Snapshot date | Repository overview |
| Independently evidenced downstream use | Unknown | Snapshot date | Public adopter or dependency evidence |

Record the repository URL, default branch, license and evidence retrieval date above the table. Enter zero when the source is available and the filtered result is empty. Leave unknown when coverage or access is incomplete. Stars and clones indicate interest and traffic. A dependency or documented integration supports a claim of adoption.

If assessing an external program, link its current terms and record which requirements this evidence can substantiate. Link a documented case from [[Signal Evidence Walkthrough]] and a verified browser run from [[Signal Workspace QA]].
